| 2026-04-20 | Deletion-content preservation guard on `upsert_post` / `upsert_comment` — **content-heuristic, not flag-based** | Live probes P1 / P2 (`verification_probes.md`) confirmed the worst case: Moltbook returns tombstoned posts and comments as `content='[deleted]'` with `is_deleted:false`. A flag-based guard alone would never fire because the API never flips the flag — tombstoning is signalled only by the content placeholder. Guard now combines (a) flag branch (`WHEN <tbl>.is_deleted = 1 OR excluded.is_deleted = 1`), (b) content-heuristic branch (`WHEN excluded.content = '[deleted]' AND <tbl>.content IS NOT NULL AND <tbl>.content != '[deleted]'`), and (c) auto-inference of `is_deleted=1` whenever incoming content is the tombstone. Applied to title/content/url on posts, content on comments. `upsert_comment` INSERT column list extended to include `is_deleted` so the flag branch compiles symmetrically. Unit-test coverage: `tests/test_snapshot_change_detection.py::test_tombstone_content_preserved_without_flag`. | Active |

| 2026-04-20 | Event-writer anchor fallback (`_snapshot_posts` / `_snapshot_agents`) | Initial Phase 3a writer skipped emission whenever no prior `*_events` row existed (`old_str is None`).
